# M6: Mobile App (Flutter)

## Status

Core local task flows, native widget extensions, and best-effort local reminders are implemented. The extensions are included in simulator builds, but adding widgets to a home screen has not been validated on either launcher or on physical devices. Widgets must be added by the user through the OS widget gallery.

## Implemented

- Generated Android and iOS Flutter projects.
- Added task validation, stable UUID creation, original/current schedules, UTC mutation timestamps, lifecycle transitions, optimistic version checks, and soft deletion.
- Added SQLite schema version 2 and a forward migration from the earlier mobile schema.
- Added today timed/untimed, overdue, legacy, future, and task history views.
- Added quick-add, task editing/rescheduling, completion/undo, cancellation/restore, and soft deletion.
- Added empty, loading, and storage-error states.
- Added unit/widget tests and native integration tests that create a task through the UI and reopen SQLite to verify persistence.
- Enabled Android core library desugaring required by `flutter_local_notifications`.
- Added Android AppWidget and iOS WidgetKit views for today's tasks and legacy summaries. Widget task rows can be completed directly; iOS queues the action until DayFlow next becomes active.
- Added in-app, platform-specific instructions for adding a widget and a control to republish its task snapshot.
- Added contextual notification-permission requests and a persistent status message when permission is denied.
- Added a ten-minute inherited reminder default with timezone-aware, inexact scheduling, cancellation, and reconciliation after task changes and app activation.

## Not Run / Remaining Risks

- Physical Android and iOS devices, release/signing builds, and cross-device behavior were not tested.
- Android notification permission flow was exercised: the runtime request displayed the system dialog, `adb shell pm grant` allowed the granted-flow test, and `adb shell pm revoke` allowed the denied-flow test. iOS permission prompt interaction was not manually driven. Exact-time delivery is intentionally not promised; Android uses inexact scheduling.
- WidgetKit and AppWidget builds plus shared snapshot/task-completion paths are integration-tested. Android launcher registration and preview were verified, but a widget was not placed on the home screen; iOS home-screen installation and physical-device behavior were not automated. The OS does not allow the app to place a widget on the user's home screen automatically.
- The notification plugin currently reports no Swift Package Manager support and uses the CocoaPods fallback.
- The version-1-to-version-2 database migration is implemented but has not been exercised against a real version-1 device database.
- Simulator verification does not guarantee behavior on every OS version, device, or background-execution condition.
