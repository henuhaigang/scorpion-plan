# M5: Release Hardening

## Status: COMPLETE

## What Changed

### Backup/Export
- **`app/backup_service.rs`**: `BackupService` with `export()` method using SQLite's built-in backup API for consistent snapshots.
- **`lib.rs`**: `export_backup` Tauri command that creates timestamped backups in the app data directory.
- **`Cargo.toml`**: Added `backup` feature to rusqlite.

### Error Handling
- All Tauri commands return `Result<T, String>` with meaningful error messages.
- `AppError` enum preserves domain vs repository error distinction.
- `RepoError` enum covers: task not found, task deleted, version conflict, category not found, database error.
- `SchedulerError` covers: permission denied, send failed.
- Database errors never appear as empty lists (PRD requirement).

### Logging
- No sensitive data (tokens, keys, PII) in logs.
- Error messages are user-facing and concise.
- Backup file paths are logged only on success.

### Packaging
- Tauri 2 bundler produces `.app` and `.dmg` on macOS.
- Bundle identifier: `com.dayflow.desktop`.
- Version: `0.1.0`.
- Icons: 32x32, 128x128, 128x128@2x, .icns, .ico.

### Signing
- V1 builds are unsigned/ad-hoc (per ADR 0007).
- macOS Gatekeeper behavior documented: users must right-click → Open on first launch.
- Developer ID + notarization is a release-gate item, not a code item.

### Auto-Update
- **Not implemented in V1** (per ADR 0007 and IMPLEMENTATION_PLAN.md M5).
- Requires security review of update channel and signing before implementation.

### Accessibility
- All interactive elements have accessible labels.
- Keyboard navigation: Tab/Shift+Tab, Enter/Space for buttons, Escape to close panel.
- Color contrast meets WCAG AA (dark text on light background, light text on dark background).
- Focus indicators visible on all interactive elements.

### Migration Verification
- SQLite migrations are versioned and forward-only.
- `schema_migrations` table tracks applied migrations.
- Backup before migration is recommended (documented in backup service).
- Existing data is preserved across migrations.

## Known Risks
1. **Unsigned macOS builds**: Users must right-click → Open on first launch. Documented.
2. **Backup file compatibility**: Backups are SQLite files; opening with a different SQLite version may cause issues. Mitigated by using the same bundled SQLite.
3. **No auto-update**: Users must manually download and install new versions. Documented.
